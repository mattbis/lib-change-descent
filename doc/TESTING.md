## behavioural testing and invariant philosophy

- this library operates at the lowest levels of shared memory and filesystem mechanics... because of this, our testing philosophy is strictly behavioral and invariant-driven...
- i do not expect any runtime errors whatsoever... traditional testing that asserts whether a function throws an error is pointless here... if a low-level operation throws, data is corrupted or the system is completely borked...
- tests are behavioral... we run real or simulated workflows, allocate shared memory pages (`SharedArrayBuffer`), trigger operations, and verify that the resulting state, node strides, hashes, and db manifests match reality without any drift or exceptions...
- invariant assertions (`libcd_invariant.mjs` and `assert_*` modules) run continuously around operation lifecycles (`run_pre_op_check`, `run_self_check`) when dev/alpha flags (`-D __LIBCD_DEV__`) are enabled...
- canaries (`0xAA` byte at stride offset 31), memory alignment guards (`assert_alignment`), and pointer bound checks (`_run_full_buffer_integrity_check`) ensure zero corruption across raw memory pools... if a canary dies or a pointer drifts out of bounds, execution halts immediately...
- automated verification runs natively via `node --test` (`npm test`) without bloated third-party frameworks... direct, fast, and mechanical execution that validates exact behavioral guarantees...
